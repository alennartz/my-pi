# DR-053: The workspace persona wins wholesale over a spawned persona, and the override is announced

## Status
Accepted

## Context
Two persona sources can meet in one session: a named specialist deployed through the `subagent` tool's `persona` parameter, and the workspace declaration at that child's cwd. The spawn path resolves both, so precedence had to be decided — and with it, what the orchestrator is told. The workspace is authoritative while its cwd is the workspace; but a silent identity swap would leave the orchestrator believing it deployed `scout` when it didn't.

## Decision
The workspace declaration wins **wholesale**: one active persona file per session, all or nothing. The spawned definition is discarded entire — fields are never merged between the two — and a field absent from the winner falls to the session's baseline, never to the discarded file's values. The switch is visible on both channels that matter: the child transcript carries an override notice (custom `persona-notice`, condition `override`) naming both the spawned agent and the winning persona, and the `subagent` tool result carries an override note (`persona 'X' overridden by workspace persona 'Y' (<cwd>)`) so the calling LLM's belief about what it deployed is corrected immediately at spawn time. Everything else is silent — announcements happen only on override: a workspace takeover of a fresh session announces nothing, because the directory IS the agent and `/sysprompt`'s projection is the pre-run visibility surface. The same precedence ladder governs model binding: a persona's `model` field is a pin that beats an explicit `model` spawn argument, which gap-fills only when the active persona declares no model — and a discarded persona's pin never applies. At the top of the ladder, an explicit launch `--system-prompt` outranks the ambient persona entirely (your own argument outranks the directory; the persona module does nothing when `customPrompt` is pre-set).

Rejected: per-field merging (take `model` from one file, `tools` from the other) — a mixed capability set is unauthorable and unreviewable, and "which file governs?" becomes unanswerable after an edit; a silent swap — deception by omission toward the party that made the deployment decision; spawned-definition-wins with the workspace as tiebreak — inverts the environment's authority: the directory is the total environment while the session is in it; retaining the losing file's fields as fallback — indistinguishable from merging once the winner omits a field.

## Consequences
"Deploy `scout`" into a persona workspace deploys the workspace's specialist, visibly — the tool result tells the orchestrator at spawn time and the override notice records it in the child's transcript. A silent identity swap is impossible; a silent *takeover* is intentional (fresh sessions announce nothing — see DR-056). The all-or-nothing rule makes every session's capability set attributable to exactly one file, which is what the construction gates (tool policy, skill resolution, model pin) key on. Cost accepted: a caller's explicit model argument can be ignored with no error when the persona pins a model — intentional, consistent with the standing "a pinned definition wins over an override" semantics.
